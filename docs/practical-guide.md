## 写在前面：90% 的「网站问题」，都是你以为没问题

做网站的人，几乎都说过这句话：

> 「我这边打开好好的啊。」

问题的本质不是用户挑剔，而是**测速方法错了**——你在公司 Wi-Fi 上测一次，只能代表你公司那条宽带；你在服务器上 `curl localhost`，只能代表机器内部。

真正靠谱的做法：

**从全国各地、全球各地、不同运营商的远端节点，向你的目标发起真实访问，把结果画在地图上。**

本文是一份**可照着做的实战手册**。全文以 **SpeedCE** 为操作示例——它现已通过下拉菜单提供 **HTTP、HTTPS、PING、TCPing、DNS、路由追踪** 六种工具，覆盖从 DNS 解析、端口连通到 Web 可用性的完整排查链路。

## 第一章：先建立正确观念——六种工具，测的不是一回事

动手之前，先分清 SpeedCE 下拉菜单里的六种检测工具各自回答什么问题。

### 1.1 PING —— 网络层通不通？

PING 使用 ICMP 协议，回答：**从检测节点到你的 IP，网络层通不通？延迟多少毫秒？**

- **适合**：VPS 验线路、判断网络层 vs 应用层故障
- **局限**：很多云服务器禁 Ping；PING 通不代表网站能打开

### 1.2 HTTP / HTTPS —— Web 服务能不能响应？

HTTP(S) 模拟真实用户访问：建立 TCP、（HTTPS 下）TLS 握手、等待响应。

- **适合**：网站上线验收、证书验证、CDN 回源检查
- **日常首选**：**HTTPS**

### 1.3 TCPing —— 禁 Ping 时，端口开不开？

TCPing 向**指定 TCP 端口**发起连接，不依赖 ICMP。

- **适合**：云服务器禁 Ping、验证 22/443/3389 等端口
- **操作**：选择 TCPing → 填写端口号 → 输入 IP

### 1.4 DNS —— 全国各地解析一致吗？

DNS 模式从各检测节点查询域名记录（A / AAAA / CNAME / MX / TXT / NS），并统计**解析一致性**。

- **适合**：改 DNS 后验收、排查部分地区解析到旧 IP
- **注意**：仅支持域名，不支持直接输入 IP

### 1.5 路由追踪 —— 慢在哪一跳？

从**选定单个节点**向目标进行 Traceroute，可选 **MTR 模式**查看丢包与延迟统计。

- **适合**：跨省/跨境慢、定位路由瓶颈
- **操作**：选择路由追踪 → 选择探测节点 → 可选 MTR

### 1.6 多节点测速 —— 把偏见变成全景

单点测速有地理偏见。SpeedCE 的「中国节点」覆盖各省三网，「全球节点」覆盖数十国城市，结果以**地图红绿分布**呈现。

## 第三章：十大高频故障场景

### 场景 1：刚买 VPS，验证商家线路

1. **PING** + 中国节点 + 三网筛选；
2. Ping 不通改 **TCPing 443**；
3. 截图地图发帖，比「我本地 ping 20ms」有说服力。

### 场景 2：迁机 / 换 DNS 后验收

1. **HTTPS** + 中国节点，测域名；
2. 配合 **DNS** 模式查 A 记录，看是否「全部节点一致」；
3. 隔 10 分钟复测 3 次，观察异常是否减少。

### 场景 3：CDN 回源 vs 节点问题

| CDN 域名 (HTTPS) | 源站 (HTTPS) | 判断 |
|------------------|--------------|------|
| 红 | 绿 | CDN 问题 |
| 绿 | 红 | 源站问题 |
| 红 | 红 | 先修源站 |

### 场景 4：微信 / QQ 打不开

SpeedCE 做 **HTTPS + 中国节点** 排除服务器问题；若全绿，更可能是微信/QQ 拦截，需 BOCE 等专项工具。

### 场景 5：HTTPS 证书过期

**HTTPS** 大面积红、**HTTP** 正常 → 高度怀疑证书；续签后复测至地图转绿。

### 场景 6：主站正常、API 挂了

分别 **HTTPS** 测 `www` 与 `api` 子域，对比两张地图。

### 场景 7：海外慢、国内正常

**HTTPS + 全球节点**；若欧美红、国内绿 → 考虑海外 CDN / 镜像。

### 场景 8：间歇性故障

**HTTPS + 中国节点**，每 15 分钟测一次，连续 6 次，记录通畅率波动。

### 场景 9：DNS 切换后部分用户仍访问旧 IP（新增）

1. **DNS** + 中国节点，查 A 记录；
2. 详情面板显示「存在 N 种解析结果」→ 局部 DNS 缓存未刷新；
3. 降低 TTL 后复测至「全部节点一致」。

### 场景 10：禁 Ping 的 VPS 不确定是否存活（新增）

1. **TCPing** + 端口 443 + 中国节点；
2. 地图多数绿色 → 服务正常，仅禁 ICMP；
3. 若 TCPing 也失败 → 查安全组、防火墙。

## 第四章：进阶技巧

### 4.1 三网分离体检法

每月固定一天：HTTPS + 中国节点，分别筛选电信/联通/移动，三张截图存档。

### 4.2 迁机前后对比法

迁机前测一次，DNS 生效后再测一次，两张地图叠在一起汇报。

### 4.3 子域清单巡检法

```
www.example.com
api.example.com
cdn.example.com
```

每月 **HTTPS + DNS(A)** 各过一遍。

### 4.4 路由追踪定位慢跳（新增）

某省 HTTPS 慢但 PING 正常时，从该省节点发起 **路由追踪（MTR）**，看哪一跳延迟飙升。

## 第七章：常见误区

1. **「我 ping 通了就没问题」** — 错，Web/证书/WAF 任一环节出错用户照样打不开
2. **「无痕模式能开，用户也该能开」** — 错，你只代表一条宽带
3. **「测一次就够了」** — 错，DNS 有缓存，网络有抖动
4. **「出了问题先换服务器」** — 错，先用六种工具定位层级
